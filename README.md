# VA Lead Radar

Telegram-бот, который ищет заказы сам: опрашивает биржи фриланса и публичные
Telegram-каналы по ключевым словам, через LLM определяет, настоящее ли это
обращение за услугами или спам, и присылает админу карточки лидов — с контактами
автора или ссылкой на объявление.

Бот не требует, чтобы его куда-то добавляли: он сам ходит за объявлениями.

## Возможности

- **Поиск без добавления в чаты.** Бот опрашивает внешние источники по
  расписанию и находит заказы сам. Два типа источников работают без ключей и
  настройки:
  - `rss` — лента биржи или доски заказов (Freelancer и любые другие с RSS);
  - `tg_public` — публичный Telegram-канал через веб-превью `t.me/s/<канал>`.
- **Контакты в карточке.** Из текста объявления извлекаются Telegram-хендл,
  email и телефон. Если контактов нет, в карточке будет ссылка на объявление
  (на бирже или на конкретное сообщение в канале).
- **Мониторинг своих чатов (дополнение).** `/addchat` добавляет чат вручную,
  либо `MONITOR_ALL_CHATS=true` — тогда бот сам берёт в работу любой чат, куда
  его добавили, с первого же сообщения. `/pause` исключает чат, `/resume`
  возвращает.
- **Ключевые слова.** `/addkeyword` добавляет слово и **сразу** прочёсывает
  текущие объявления в источниках, присылая найденное карточками — ждать
  следующего цикла не нужно. Дальше слово работает постоянно: всё новое, что
  подходит, приходит само. По умолчанию стоят «ищу разработчика», «нужен сайт»,
  «нужен бот», «закажу дизайн» плюс более широкий набор формулировок, которые
  реально встречаются на биржах.
- **Совпадение по словам, а не по подстроке.** Короткое слово не сработает внутри
  другого: `бот` не поймает «работа», `сайт` — «сайты». Так что короткие слова
  можно добавлять спокойно.
- **LLM-фильтр.** Объявление с ключевым словом уходит в Gemini или OpenAI с
  промтом, который просит вернуть JSON `{is_lead, summary, intent}`. Модель
  отсеивает рекламу, спам и предложения услуг.
- **Анти-дубли.** Хэш сообщения (`chat_id:message_id`) или источника
  (`source:external_id`) хранится как первичный ключ, поэтому один лид не придёт
  дважды — даже после перезапуска и даже если лента отдаёт всю историю заново.
- **Два режима работы.** Long polling для локального запуска, VPS и Docker.
  Webhook с эндпоинтом `/health` для бесплатных хостингов, где процесс засыпает
  и диск очищается. Опрос источников работает в обоих режимах.
- **Две СУБД.** SQLite-файл для локальной работы, Postgres (Neon, Render) там,
  где диск не сохраняется.
- **Логирование и обработка ошибок.** Лог в файл; сбой LLM, источника или БД не
  роняет бота и не мешает остальным источникам.

## Чего бот не может

Это важно понимать до настройки:

- **Обычные (непубличные) чаты.** Bot API не отдаёт сообщения из чатов, где бота
  нет, а веб-превью работает только для публичных каналов. Чтобы читать обычные
  группы и искать по всем чатам, нужен **userbot** — вход под реальным
  аккаунтом (MTProto). Он выключен по умолчанию, требует `pip install telethon`
  и ключей `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` / `TELEGRAM_SESSION`.
  Автоматизация пользовательского аккаунта может привести к ограничениям или
  блокировке — включайте, только если понимаете риск.
- **Закрытые биржи.** Upwork отдаёт RSS только с ключом (403 без него), Kwork
  публикует услуги исполнителей, а не заказы. Любую биржу с открытым RSS можно
  добавить через `/addsource rss <url>`.

## Требования

- Python 3.11+
- Токен бота от [@BotFather](https://t.me/BotFather)
- Ваш Telegram ID (узнать можно у [@userinfobot](https://t.me/userinfobot))
- Ключ LLM: [Google AI Studio](https://aistudio.google.com/apikey) (Gemini) или
  [OpenAI](https://platform.openai.com/api-keys)

## Быстрый старт (локально, long polling)

```bash
git clone <repo-url> va-lead-radar
cd va-lead-radar

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # заполните BOT_TOKEN, ADMIN_ID, LLM_API_KEY
python bot.py
```

При старте бот пишет в лог, под каким аккаунтом авторизовался, создаёт файл
`data/va_lead_radar.db`, наполняет список ключевых слов и добавляет стартовые
источники. Первый опрос источников пройдёт сразу, дальше — каждые `POLL_INTERVAL`
секунд. Чтобы не ждать, отправьте боту `/poll`.

## Настройка

Всё через `.env` (см. `.env.example`).

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather. |
| `ADMIN_ID` | для доставки | Ваш числовой Telegram ID. Без него бот работает и пишет лиды в базу, но карточки не отправляет (в лог идёт предупреждение). |
| `LLM_API_KEY` | да | Ключ Gemini или OpenAI. |
| `LLM_PROVIDER` | нет | `gemini` (по умолчанию) или `openai`. |
| `LLM_MODEL` | нет | Модель. По умолчанию `gemini-1.5-flash` или `gpt-4o-mini`. |
| `LLM_FALLBACK_MODELS` | нет | Список моделей через запятую — пробуются по очереди, если основная не ответила (лимиты, сбои). Полезно на бесплатных тарифах. |
| `OPENAI_BASE_URL` | нет | Свой OpenAI-совместимый шлюз (например, OpenRouter). |
| `DATABASE_URL` | для хостинга | Строка подключения Postgres, вместе с `?sslmode=require`. Пусто — используется SQLite. |
| `MONITOR_ALL_CHATS` | нет | `true` — брать в мониторинг все чаты, куда добавлен бот, без `/addchat`. По умолчанию `false`. |
| `POLL_SOURCES` | нет | `false` полностью выключает фоновый опрос источников. По умолчанию `true`. |
| `POLL_INTERVAL` | нет | Пауза между опросами в секундах, минимум 60. По умолчанию `900`. |
| `MAX_ITEM_AGE_DAYS` | нет | Не присылать объявления старше стольких дней. По умолчанию `30`, `0` — без ограничения. |
| `SEED_DEFAULT_SOURCES` | нет | `false` — не добавлять стартовые источники и слова при первом запуске. |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` | для userbot | Доступ к обычным чатам и поиску. Без них userbot-источники просто пропускаются. |
| `DB_PATH` | нет | Путь к файлу SQLite. По умолчанию `data/va_lead_radar.db`. |
| `WEBHOOK_BASE_URL` | для хостинга | Публичный `https`-адрес сервиса. Пусто — long polling. |
| `WEBHOOK_SECRET` | рекомендуется | Секрет, который Telegram присылает в заголовке. Бот хэширует его, чтобы получить допустимый для Telegram токен. |
| `PORT` | нет | Порт HTTP-сервера. Хостинг подставляет свой, локально 8080. |
| `LOG_PATH`, `LOG_LEVEL` | нет | Куда и как подробно писать лог. |

## Команды

### Внешние источники (основной режим)

| Команда | Что делает |
|---|---|
| `/sources` | Список источников и их состояние. |
| `/addsource <тип> <адрес>` | Добавить источник. Типы: `rss`, `tg_public`, `userbot`. |
| `/removesource <тип> <адрес>` | Удалить источник. |
| `/pause_source <тип> <адрес>` | Поставить источник на паузу. |
| `/resume_source <тип> <адрес>` | Вернуть источник в работу. |
| `/poll` | Опросить все источники прямо сейчас. |

### Чаты, куда добавлен бот

| Команда | Что делает |
|---|---|
| `/addchat <chat_id>` | Добавить чат или канал в мониторинг. |
| `/remove chat <chat_id>` | Убрать чат. |
| `/pause [chat_id]` | Поставить чат на паузу. Без аргумента — тот чат, где написана команда. |
| `/resume [chat_id]` | Снять чат с паузы. |

### Ключевые слова и прочее

| Команда | Что делает |
|---|---|
| `/addkeyword <слово>` | Добавить ключевое слово и сразу поискать по нему в источниках. |
| `/remove keyword <слово>` | Убрать ключевое слово. |
| `/list` | Показать источники, чаты (с пометкой паузы) и ключевые слова. |
| `/settings` | Текущие настройки: источники, опрос, модель, чаты, слова. |
| `/export` | Прислать настройки JSON-файлом. |
| `/stats` | Сколько источников, чатов, слов и найденных лидов. |
| `/start` | Справка. |

Команды доступны только админу (`ADMIN_ID`).

## Источники: как добавить и что работает

### Биржи и доски заказов (`rss`)

Подходит любая площадка, отдающая открытый RSS с заказами:

```
/addsource rss https://www.freelancer.com/rss.xml
```

Проверено, что отдают заказы без ключа: `freelancer.com`, `weworkremotely.com`.
Не подходят: `upwork.com` (RSS только с ключом), `kwork.ru` (лента услуг, не
заказов), `freelance.habr.com` (страница на JS, данных в HTML нет).

### Публичные Telegram-каналы (`tg_public`)

Бот читает публичную веб-версию канала, поэтому добавлять его в канал не нужно:

```
/addsource tg_public zakazy_it
/addsource tg_public https://t.me/freelance_zakazy
```

Любая запись вида `@name`, `name` или `t.me/name` приводится к одному виду, так
что один канал нельзя случайно добавить дважды.

Проверено, что канал живой: `freelance_zakazy` (~18 мин между постами),
`zakazy_it`. Не подходят: `freelance_orders`, `workzilla`, `kwork_orders` —
последние посты 2023 года, лента мертва.

Ограничения: работают только публичные каналы с `@username`; превью показывает
примерно 20 последних постов, поэтому не стоит сильно увеличивать
`POLL_INTERVAL`.

### Обычные чаты и поиск (`userbot`, необязательно)

Bot API не читает чужие чаты, поэтому для них нужен вход под реальным аккаунтом:

```bash
pip install telethon
```

1. Получите `api_id` и `api_hash` на https://my.telegram.org.
2. Сгенерируйте строку сессии:

```bash
python -c "from telethon.sync import TelegramClient; \
from telethon.sessions import StringSession; \
print(StringSession.save(TelegramClient(StringSession(), API_ID, 'API_HASH').start()))"
```

3. Пропишите `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` в `.env`.
4. Добавьте источник — конкретный чат или глобальный поиск:

```
/addsource userbot @some_chat
/addsource userbot search:нужен разработчик
```

Без ключей такие источники просто пропускаются при опросе, остальное работает
как обычно. Помните: автоматизация пользовательского аккаунта может привести к
ограничениям или блокировке.

### Авторежим: все чаты сразу

По умолчанию бот мониторит только то, что добавлено через `/addchat`. Чтобы он
брал в работу любой чат, куда его добавили, поставьте `MONITOR_ALL_CHATS=true`.

Как это работает:

- Чат регистрируется в момент первого сообщения в нём — вместе с названием.
- Личные переписки не затрагиваются, только группы, супергруппы и каналы.
- Исключить конкретный чат можно через `/pause`: запись остаётся в базе, и бот
  больше не подхватит этот чат заново. `/resume` возвращает его в работу.

Так удобно, когда чатов много и добавлять их по одному лень: добавили бота в
нужные чаты — он сам всё подобрал, а лишнее отключили парой команд.

### Как узнать `chat_id`

Добавьте бота в чат, отправьте туда сообщение и откройте
`https://api.telegram.org/bot<TOKEN>/getUpdates` — в ответе будет `chat.id`
(у групп он отрицательный, например `-1001234567890`). Для каналов добавьте бота
администратором и используйте `@username` канала или его ID.

> **Важно.** У бота должен быть **отключён privacy mode**, иначе Telegram не
> отдаёт боту обычные сообщения из групп и мониторинг не работает. Отключить:
> @BotFather → `/mybots` → ваш бот → *Bot Settings* → *Group Privacy* → *Turn off*.
> После этого удалите и заново добавьте бота в чат.

## Как это устроено

1. **Опрос.** Фоновый цикл (`app/poller.py`) раз в `POLL_INTERVAL` секунд обходит
   все активные источники и получает список свежих объявлений.
2. **Ключевые слова.** Объявление без ключевого слова отбрасывается сразу, без
   обращения к LLM — так экономится квота. Слово проверяется по границам слов
   (см. `keyword_pattern` в `app/db.py`), поэтому `бот` не ловит «работа».
   `/addkeyword` дополнительно запускает разовый проход по текущим объявлениям
   (`Poller.scan_backlog`), чтобы результат был сразу.
3. **Дедупликация.** Хэш `source:external_id` проверяется по таблице `leads` и
   пишется туда же первичным ключом, поэтому ни один лид не придёт дважды.
4. **LLM.** Текст уходит в модель с промтом, который требует JSON
   `{is_lead, summary, intent}`. Модель отсеивает рекламу и предложения услуг.
5. **Карточка.** Из текста извлекаются контакты; если их нет — в карточку
   попадает ссылка на объявление. Лид уходит админу.
